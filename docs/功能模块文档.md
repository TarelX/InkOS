# InkOS V2 功能模块文档

> 面向二次开发与运维的模块级说明。安装与运行方式见根目录 `README.md`；
> 架构决策与迁移历史见 `docs/v2/` 下各文档。

---

## 1. 总体架构

```
┌────────────────────────────────────────────────────────────┐
│ apps/desktop        Electron 桌面壳（打包 Studio 为 exe）     │
├────────────────────────────────────────────────────────────┤
│ packages/studio     Studio 服务端(Hono API/SSE) + React 前端 │
├────────────────────────────────────────────────────────────┤
│ packages/core       核心库（Agent / 写作管线 / V2 子系统）    │
├────────────────────────────────────────────────────────────┤
│ SQLite（node:sqlite）+ 文件系统（版本化产物 / 书稿 / 素材）    │
└────────────────────────────────────────────────────────────┘
```

- **monorepo**：pnpm workspace（`packages/*`、`apps/*`）。
- **数据落盘**：一个"项目目录"承载全部状态（书籍、产物、数据库、会话），
  Studio 启动参数即项目目录，天然支持多项目隔离与整目录备份。
- **无 LLM 可运行**：所有 V2 管线都有确定性基线执行器，未配置模型服务时
  可离线跑通全流程（用于验证与 CI）。

## 2. packages/core — 核心库

### 2.1 V2 子系统（本 fork 的主体增量）

| 模块 | 路径 | 职责 |
|---|---|---|
| 项目库 | `src/v2/project-db.ts` | 项目级 SQLite（`.inkos/inkos-v2.sqlite`）连接与迁移，WAL 模式 |
| 资产注册 | `src/v2/asset-registry.ts` | skill/rule/schema/template/evaluator 资产的清单、校验和与信任级别 |
| 版本化产物仓库 | `src/artifacts/` | 不可变产物存储（`.inkos/artifacts/<id>/vNNNNNN/`），manifest（状态 draft/accepted/rejected/superseded、输入依赖、内容哈希）+ SQLite 加速索引 + 过期检测 |
| 工作流引擎 | `src/workflow/` | 持久化 DAG：模板编译（`template.ts`）→ 运行/节点/事件/审批持久化（`run-repository.ts`）→ 引擎（`engine.ts`：执行、门禁、重试、人工审批、崩溃恢复、过期传播）；支持项目级模板加载（`template-loader.ts`） |
| 故事智能层（深度拆文） | `src/story-intelligence/` | 规则分场（scene）→ LLM 事件抽取（带原文引句校验）→ 实体解析（不自动合并，出合并提案）→ 因果连边（窗口化）→ 故事线聚类 → 节奏报告；全部 Schema 化（`schemas/`），内容寻址 ID（`ids.ts`），可断点续跑（checkpoint） |
| 改编管线 | `src/adaptation/` | `AdaptationContract`（必须保留/可变更/禁区）→ 事件取舍映射 → 人物映射（改名/合并）→ 目标主线骨架 → 章级契约 → 正文生成 → 保真审计；硬门禁（契约覆盖率/因果完整性/角色出处，`gates.ts`）；工作流模板 `novel-adaptation` 与分析专用 `novel-analysis` |
| 原创管线 | `src/creation/` | 创作简报 → 概念孵化 → Canon 世界观圣经（规则/人物/冲突引擎）→ 主线骨架 → 卷纲 → 章级契约 → 正文 → 章审计 → 状态结算；工作流模板 `new-novel` |
| V1→V2 迁移 | `src/migration/v1-to-v2.ts` | 扫描 V1 书籍 → 干跑报告 → 沙箱验证 → 增量导入为 `v1-import.deconstruct` 产物（参考级数据） |
| 统一出口 | `src/v2/index.ts` | 以上模块经 `@actalk/inkos-core/v2` 子路径导出 |

## 4. apps/desktop — 桌面壳

Electron 主进程（`main.cjs`）直接加载 monorepo 构建出的 Studio；
`scripts/build-desktop.ps1` 用 `pnpm deploy --legacy` 落 Studio 资源后经
electron-builder 产出绿色目录版与 Windows 安装包。

## 5. 数据库（SQLite，DDL 见 `db/`）

| 库 | 位置 | 表 | 用途 |
|---|---|---|---|
| V2 项目库 | `<项目>/.inkos/inkos-v2.sqlite` | `artifact_index`、`workflow_runs`、`workflow_nodes`、`workflow_events`、`workflow_approvals`、`schema_migrations` | 产物索引与工作流持久化（引擎崩溃恢复的依据） |
| 书籍记忆库 | `<项目>/books/<书>/story/memory.db` | 章节记忆/实体/事实等 8 个对象 | 写作管线的长程记忆与检索 |
| 游玩运行库 | `<项目>/worlds/<id>/runs/<run>/play.db` | 游玩状态 8 个对象 | 开放世界互动游玩 |

三个库均由代码迁移**在运行时自动建表**，`db/*.schema.sql` 仅供查阅审计；
`db/dump-schema.mjs` 可随时从现有库重新导出结构。

## 6. 数据目录约定（项目目录）

```
<项目目录>/
  inkos.json            项目配置（名称/版本/默认模型等）
  .inkos/               状态目录
    inkos-v2.sqlite     V2 项目库
    artifacts/          版本化产物（<artifactId>/vNNNNNN/ 内容+manifest）
    sessions/ uploads/  会话与上传
  books/<书名>/          书稿（chapters/）、设定（story/）、记忆库
  worlds/               互动世界
```

## 7. 关键流程速查

- **原著深度拆文**：工作台顶栏「深度拆文」→ `novel-analysis` 模板 →
  scenes/events/entities/causal-graph/storylines/pacing 六类产物 → 第四栏总览升级为可验证数据。
- **发起改编**：原著书顶栏「发起改编 → 选目标书」→ 目标书跑 `novel-adaptation` →
  契约审批（人工）→ 映射 → 骨架 → 章级契约 → 正文 → 保真审计（硬门禁不过即失败可重试）。
- **原创新书**：顶栏输入一句话创意 →「新建工作流」→ `new-novel` 全管线，
  Canon 与主线骨架节点带人工审批门。
- **人物羁绊**：第四栏人物关系 Tab「生成人物羁绊」→ LLM 对共现人物对分类
  （盟友/敌对/师徒/亲属…）→ `analysis.character-relations` 产物 → 图谱语义化着色。
